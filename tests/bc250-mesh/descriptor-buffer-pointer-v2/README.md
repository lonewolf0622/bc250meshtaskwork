Descriptor-buffer-pointer-v2 audits the ordinary Task+Mesh tiny route with a descriptor buffer at set 0, a bufferless push descriptor root CBV at set 1, and an application push constant consumed by Task, Mesh, and Fragment.

Run with `ICD`, `SHIM`, `POLICY`, and optionally `KEEP` set, using `bash run.sh`. `SHIM` must support gfx1013. The launcher hides the real device nodes with bwrap; the fixture requires the noop shim and has no hardware entry point. It removes the unused DGC device feature request from the inherited MONO fixture, so the same setup can run against builds without DGC exposure. Existing gates and freeze pins are not modified.

The driver capture switch `BC250_CAPTURE_POINTERS=1` records CPU uploads and shader constant/descriptor sources. The checker interprets SET_SH_REG and LOAD_SH_REG_INDEX, selects the uploaded Task producer, Mesh consumer, and Fragment at their actual dispatches, and validates all live pointer pairs and 32-bit descriptor addresses against captured memory. It verifies descriptor resources contain 11 and 13, and application constants contain 7. Shader code hashes and masks are pinned; changed code, missing captures, ambiguous dispatches, or unsupported register loads fail closed. Scratch, indirect draw inputs, and an indirect descriptor set table are not consumed by this tiny fixture; a live indirect table must resolve if present.

The application Fragment uses compatibility words 6/7 after lowering. Redirecting those inline words to application offsets 24/28 produces a null base, even though a noop submission reports success. The same checker rejects the pre-fix capture with `null application base stage=4`. The fixed capture checks 12 pointers; 12 null injections at their resolved pointer boundaries must all be rejected. No rendered-pixel or hardware-completion claim is made.
