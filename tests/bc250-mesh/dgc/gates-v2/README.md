These fresh one-shot entries are named `descriptor-buffers-v2` and `many-task-v2`. Build with `python3 build.py FREEZE CANDIDATE_SO POLICY_JSON PASSED_D2_RECEIPT`. The destination must not exist. The builder pins the candidate, policy, shaders, audit, launcher and historical passed D2 prerequisite. It never modifies a previous gate or its reservation.

For offline execution, hide real devices with bwrap and preload a gfx1013 noop DRM shim; invoke `run_once.py --offline NAME`. For a separately authorized hardware execution, invoke `run_once.py --authorized-gpu-NAME`. Each new name reserves its own marker with O_EXCL before either MONO or feature submission. Failure retains that reservation and stops without retry.

Descriptor-buffers-v2 enables CPU pointer and command captures. Before writing the hardware release token, it audits the MONO IB or the generated DGC template, checks every lowered Task/Mesh/Fragment constant source, resolves descriptor-buffer and push-descriptor resources, and validates the live private pointers. Missing or inconsistent captures stop before submission. Many-task-v2 preserves the original 64-draw/count fixture, visibility ordering, and pixel comparison. Neither build nor offline execution reserves hardware markers.
